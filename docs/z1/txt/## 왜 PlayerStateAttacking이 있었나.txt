 ## 왜 PlayerStateAttacking이 있었나

  원래 의도는 다른 클라이언트에서도 검 공격 표현을 보이게 하는 것이었습니다.

  Player A 입력
  → 서버 공격 시작
  → 일정 Tick 동안 attacking 상태
  → Snapshot에 PlayerStateAttacking
  → MyPlayer/NetworkPlayer 앞에 검 Sprite 표시

  즉:

  - InputActionAttack: 공격을 시작해 달라는 순간 입력
  - attackRequested: 서버가 아직 처리하지 않은 입력
  - PlayerStateAttacking: 서버가 현재 공격 표현 중이라고 확정한 상태

  입니다.

  ## 지금 당장 필요한가?

  현재 구현하려는 것이 아래 범위뿐이라면 필요 없습니다.

  A 입력
  → 즉시 Sword AABB 검사
  → Enemy HP 감소
  → Enemy 사망·제거

  공격을 한 Tick의 즉시 판정으로 처리하고 검 Sprite나 공격 지속 시간, 재공격 cooldown을 아직 구현하지 않
  는다면 PlayerStateAttacking은 계속 0이어도 됩니다.

  ## 제거해야 하나?

  두 선택 모두 가능합니다.

  1. 당장 두고 사용하지 않기
     이후 NetworkSwordEffect를 구현할 예정이므로 wire layout 변경 없이 사용할 수 있습니다.

  2. 최소 구현 원칙에 따라 제거하기
     PlayerStateAttacking, NetworkPlayer::IsAttacking() 등 미사용 코드를 제거하고 실제 공격 표현 작업 때
     다시 추가합니다.

  지금 다음 단계가 바로 공격 시각화까지 포함될 가능성이 있으므로, 저는 상수는 그대로 두되 현재 피해 판정
  에서는 사용하지 않는 쪽을 권합니다. wire 크기에는 변화가 없고 기능에도 영향을 주지 않습니다.

  핵심은 PlayerStateAttacking을 C2S_Input 검사에 사용하지 않는 것입니다. 이 값은 나중에 서버가 Snapshot
  을 만들 때만 설정하는 출력 상태입니다.


  클라이언트 NetworkEnemy도 _flags에 저장만 하고 공격 표현에는 사용하지 않습니다.
  두 flag의 의도는 다음과 같습니다.

  - PlayerStateAttacking: 검을 휘두르는 Player 표현
  - EnemyStateAttacking: Enemy의 공격 준비·공격 동작 표현

  ## Player 공격 표현

  Player는 별도 Sword Snapshot이 없으므로 PlayerStateAttacking을 검 표현에 사용할 수 있습니다.

  서버 attackTicksRemaining > 0
  → PlayerStateAttacking 설정
  → 클라이언트가 Player 앞에 NetworkSwordEffect 표시
  → flag가 꺼지면 효과 제거

  클라이언트는 매 Snapshot마다 검을 새로 생성하면 안 되고, 상태 변화에 맞춰 관리해야 합니다.
  또는 공격 중인 동안 Player에 부착된 검 Actor 하나를 유지하는 방식도 가능합니다.

  ## Enemy 공격 표현

  EnemyStateAttacking은 Projectile 생성 자체보다 Enemy의 공격 모션에 적합합니다.

  EnemyStateAttacking
  → Moblin이 창을 던지는 자세 또는 색상 표시
  → 필요하면 공격 효과음 재생

  Projectile 생성·제거는 이미 별도의 SnapshotProjectileState가 원본입니다.

  Snapshot projectiles 배열에 ID 등장
  → NetworkProjectile 생성

  배열에서 ID 사라짐
  → NetworkProjectile 제거

  EnemyStateAttacking을 보고 Projectile을 생성하면 안 됩니다. Snapshot은 매 Tick 반복 수신되므로 같은 공
  격에서 Projectile이 여러 개 생성될 수 있고, 중간에 접속한 클라이언트의 상태도 실제 서버 Projectile과
  달라질 수 있습니다.
